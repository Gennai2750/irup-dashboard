# 単価とスキルの棚卸しダッシュボード

iRup 総会ワークショップ用のリファレンス実装。

職種・現在の単価・保有技術・AI活用状況・空き時間を入力すると、
「目標の単価に必要な技術のうち、何がどれだけ残っていて、いまのペースだといつ到達するか」を
その場で組み替えて表示する 1 ページのアプリ。

## 動かし方

```bash
npm install
npm run dev      # http://localhost:3000
```

本番ビルドを確認する場合:

```bash
npm run build && npm start
```

> 初回の `npm run dev` はコンパイルに 20〜30 秒かかります（後述の Babel 経由のため）。2 回目以降は速くなります。

## 画面

### ヒアリングタブ

| # | 入力 |
| --- | --- |
| 01 | 現在の職種（6 種）。**「作業の名前」ではなく「触っている対象」で選ばせる** |
| 02 | 現在の単価（40〜120 万円・5 万円刻み） |
| 03 | 現在の保有技術（職種別のチェックボックス ＋ 理解度 3 段階） |
| 04 | AI をどれだけ使ったことがあるか（5 段階） |
| 05 | 技術以外の能力（チェックボックス ＋ 理解度 3 段階） |
| 06 | 現在の空き時間（週の休日数・平日 1 日・休日 1 日） |
| 07 | 目標の単価 ＋ 1 日あたりの学習時間 |

#### 職種の分け方

キッティング・ヘルプデスク・監視といった**作業名では境界が引けない**ため、
職種は「主に触っている対象」で分けている。作業の“深さ”は職種ではなくレイヤーで表す。

| 主に触っているもの | 職種 |
| --- | --- |
| 物理サーバ・OS・仮想化基盤 | インフラ（オンプレ・サーバ） |
| AWS / Azure / GCP のコンソールや IaC | インフラ（クラウド） |
| ルータ・スイッチ・ファイアウォールの設定 | ネットワーク |
| 利用者のPC・アカウント・問い合わせ | 社内IT・ヘルプデスク |
| 画面・UI のコード | 開発（フロントエンド） |
| サーバサイドのコード | 開発（バックエンド） |

同じ「キッティング」でも、サーバのラッキングや初期構築ならインフラ（オンプレ・サーバ）、
利用者PCのセットアップなら社内IT・ヘルプデスクに分かれる。

#### レイヤーと単価帯

| レイヤー | 単価帯 | 求められること | 必要AI活用レベル |
| --- | --- | --- | --- |
| 定型作業 | 40〜45 万 | 手順書のとおりに、決められた作業を止めずに終わらせる | 1 |
| 運用・保守 | 50〜55 万 | 手順の範囲で判断し、切り分けと一次対応ができる | 2 |
| 構築 | 60〜70 万 | 決まった設計を、自分の手で組み上げる | 3 |
| 設計 | 75〜90 万 | 要件から構成を決め、選んだ根拠を説明できる | 4 |
| アーキテクト・リード | 95 万〜 | 技術選定と全体設計を持ち、人を動かす | 5 |

## 到達時期の出し方

```
目標単価 → レイヤー（定型作業／運用・保守／構築／設計／アーキテクト）
  → そのレイヤーで求められる技術・技術以外の能力・AI活用レベル
  − いま持っているもの（理解度に応じた残り割合）
  = 残っている学習時間
  ÷ (1日あたりの学習時間 × 30.45日) = 到達までの月数 → 到達年月
```

**学習時間から単価が上がることを保証する計算ではありません。**
「その水準で求められる項目を、いまのペースで学び終えるのはいつか」を出しているだけです。

### 試算の前提（画面の 02 にも明示している）

- 各項目の標準学習時間は、資格試験の学習時間の目安をもとに置いた値。実測値ではない
  （例：AWS SAA は初心者 50〜80 時間・実務経験者 20〜50 時間とされる）
- 理解度ごとに残っている学習時間の割合：教えられる 0% ／ 業務でやっている 30% ／ かじった 60% ／ 未チェック 100%
- AI活用は、目標レイヤーで求められるレベルまで 1 段あたり 20 時間
- 1ヶ月 ＝ 30.45 日（4.35 週 × 7 日）

単価帯とレイヤーの境界、および各技術の標準学習時間は、公開されている単価相場の記事をもとに置いた目安です。
**実運用では社内の実単価・実感に合わせて `lib/constants.ts` を調整してください。**

## 技術スタック

| 領域 | 採用 | 補足 |
| --- | --- | --- |
| フレームワーク | Next.js **15.5** / App Router | 16 系ではなく 15 系を固定（理由は下記） |
| 言語 | TypeScript | `strict: true` |
| スタイル | **StyleX** 0.19 | `@stylexjs/babel-plugin` ＋ `@stylexjs/postcss-plugin` |
| 状態管理 | React `useState` / `useMemo` | ライブラリなし。状態は `app/page.tsx` の 1 か所に集約 |
| フォント | Google Fonts（`<link>` 読み込み） | Noto Serif JP / Noto Sans JP / Roboto Mono |

### なぜ Next.js 15 系なのか

StyleX の公式セットアップは `babel.config.js` に Babel プラグインを置く方式で、
**Babel を使うと SWC が無効になり、Turbopack が使えません**。
Next.js 16 は Turbopack が既定なので、Babel 前提の StyleX とは噛み合いが悪い。
そのため webpack を既定で使える 15 系を固定しています（`next dev` に `--turbopack` を付けないこと）。

`next/font` も Babel 構成では使えないため、フォントは `app/layout.tsx` の `<link>` で読み込んでいます。

### StyleX でハマるところ（重要）

**`border` / `borderTop` / `borderBottom` / `borderLeft` などのショートハンドは黙って捨てられます。**
エラーも警告も出ないまま枠線が消えるので、必ず longhand で書くこと。

```ts
// ✗ 効かない
border: `1px solid ${colors.border}`,

// ○ こう書く
borderWidth: '1px',
borderStyle: 'solid',
borderColor: colors.border,
```

`padding` / `margin` / `gap` / `flex` / `transition` のショートハンドは問題なく通ります。
`<span>` に `height` を効かせたい場合は `display: 'block'` を明示すること。

`@stylexjs/eslint-plugin` を入れれば静的に検出できます。

## ディレクトリ構成

```
app/
  layout.tsx            html/head（フォント読み込み）
  globals.css           リセット ＋ @stylex ディレクティブ
  tokens.stylex.ts      色・フォント・角丸・影のトークン
  page.tsx              状態（FormState）とタブ切り替え
lib/
  constants.ts          職種・単価帯・レイヤー・技術項目・標準学習時間・理解度の割合
  calc.ts               計算だけを持つ純関数（derive / buildGap / arrivalDate …）
  format.ts             表示整形（n1 / n0 / trunc1 / span / ym …）
components/
  ui/                   Card / ChoiceButtons / HourInput / SkillChecklist
  hearing/              01〜07 の入力ブロック
  result/               判定 ＋ 01〜08 ＋ 出典
```

## 設計上の約束

- **指定されていない係数・補正値を作らない。** 使ってよい数値は `lib/constants.ts` に集めた値と、暦の定数（24 時間 / 7 日 / 4.35 週）だけ。
  試算のために置いた前提（理解度の割合・AI活用 1 段あたりの時間）は、必ず画面上に明示する。
- **「計算する」ボタンは作らない。** 入力が変わった時点で `useMemo` が再計算する。
- **極端な入力で壊れない。** 空き時間や学習時間が 0 のとき、割合や月数は `—` と表示しゼロ除算しない。
- **判定文は事実だけ。** 届かない人を否定する書き方をしない。
- **`08 今日、最初に手をつけること` は必ず空欄。** 学習内容の提案や診断文を書き足さない。

## 出典

- 単価帯：AWS 関連のフリーランス公開案件では月 60〜90 万円が中心、上位帯で月 100〜130 万円とされる（2026 年上半期）。
  インフラエンジニアは月 55〜100 万円、システムエンジニアは月 50〜120 万円が相場として示されている。
  いずれも人材紹介事業者が公開している相場記事にもとづく参考値で、公的統計ではない。
- レイヤーの考え方：単価差は経験年数よりも担当レイヤー（運用／構築／設計／アーキテクト）と、
  IaC・コンテナ・セキュリティなどの掛け合わせスキルの有無で開くとされる。
- 標準学習時間：AWS 認定ソリューションアーキテクト アソシエイト（SAA）の学習時間は、
  初心者で 50〜80 時間、実務経験者で 20〜50 時間が目安とされる。
- 学習状況の背景：勤務先以外での学習・自己啓発について「とくに何も行っていない」と答えた就業者は日本で 52.6%、
  調査対象 18 ヵ国・地域中で最も高い＝パーソル総合研究所『グローバル就業実態・成長意識調査』（2022 年）。
