## 0. 読み方

### 0-1. 3つの文書の役割

| 文書 | 決めること |
| --- | --- |
| `CLAUDE.md` | **どう書くか** — スタック、ファイル構成、名前、StyleX の書き方 |
| **この仕様書** | **何を作るか** — 画面、文言、計算式、壊れない条件 |
| `データ定義.md` | **使う値** — 6職種 ＋ 技術以外、全129項目の名前と時間 |

### 0-2. いちばん大事な原則

> **書いていない数字を作らないこと。**

「空き時間のうち実際に使える割合は70%くらいだろう」といった、
それらしい補正係数を勝手に掛けてはいけません。
使ってよい数値は **3章の固定値**、**`データ定義.md` の値**、**暦の定数（24時間 / 7日 / 4.35週）** だけです。

仕様に書いていないことが出てきたら、**その場で決めずに質問してください。**
勝手に決めた1つの数字が、全員の出力がズレる原因になります。

### 0-3. 逐語指定について

**「」で囲った文言は、そのまま使ってください。** 言い換え・省略・追加をしないこと。
レイアウトや余白は任せます。

## 1. 作るもの

**1ページ・2タブ構成の Web アプリ。**

| タブ | 役割 |
| --- | --- |
| **ヒアリング** | 6つのブロックで、いまの職種・単価・スキル・空き時間・目標を入力する |
| **結果** | 「目標の単価に届くには、毎日どれだけ学べばいいか」を出す |

### 1-1. このアプリが答えること

> **いつまでに、いくらの単価になりたいか** を入れると、
> **毎日何時間、何を勉強すればいいか** が出る。

「いつ到達しますか」を出すのではありません。**期限を聞いて、1日あたりを逆算します。**
「◯年後に届きます」より「毎日これをやりましょう」のほうが、明日から動ける形になるためです。

### 1-2. 全体の約束

1. **「計算する」ボタンを作らない。** 入力が変わった時点で結果が組み替わる
2. **状態は1か所に集約する。** 2つのタブは同じ入力を見る。行き来しても消えない
3. **保存・送信・ログインをしない。** 画面を閉じたら消えてよい。サーバー通信は一切なし
4. **他人と比べる機能を作らない。** 1人で完結する

## 2. 言葉の定義

この2つが、このアプリの考え方の軸です。

### 2-1. レイヤー ― 単価は「どこまで担当できるか」で決まる

単価の差は、経験年数よりも**担当できるレイヤー**で開きます。

| レイヤー | `key` | 単価帯 | 求められること |
| --- | --- | --- | --- |
| 定型作業 | `routine` | 40〜45万 | 手順書のとおりに、決められた作業を止めずに終わらせる |
| 運用・保守 | `ops` | 50〜55万 | 手順の範囲で判断し、切り分けと一次対応ができる |
| 構築 | `build` | 60〜70万 | 決まった設計を、自分の手で組み上げる |
| 設計 | `design` | 75〜90万 | 要件から構成を決め、選んだ根拠を説明できる |
| アーキテクト・リード | `arch` | 95万〜 | 技術選定と全体設計を持ち、人を動かす |

### 2-2. 「扱える」と「教えられる」

技術項目はそれぞれ、**2つの学習時間**を持ちます。

| ゴール | 意味 | フィールド名 |
| --- | --- | --- |
| **扱える** | 手を動かして成果物を出せる | `useHours` |
| **教えられる** | **なぜそれを選んだかを説明でき**、人に教えられる | `teachHours` |

そして **到達点は、目標レイヤーによって変わります。**

> **目標レイヤーの技術は「扱える」まで。**
> **それより下のレイヤーの技術は「教えられる」まで。**

下の層を説明できないと、その上の設計・技術選定はできないためです。
これが、このアプリがいちばん言いたいことです。**必ずこのルールで実装してください。**

## 3. 固定値

**ここに書かれた数値以外を、計算に登場させてはいけません。**

### 3-1. 暦・単位

| 名前 | 値 | 用途 |
| --- | --- | --- |
| `WEEKS_PER_MONTH` | **4.35** | 1ヶ月＝4.35週 |
| `DAYS_PER_WEEK` | 7 | 平日日数 ＝ (7 − 週休日数) |
| `DAYS_PER_MONTH` | `4.35 × 7` ＝ **30.45** | 1日あたりの計算に使う |
| `HOURS_PER_DAY` | 24 | 入力の上限 |

1ヶ月の日数は **30.45日**です。**30日や31日を使わないこと。**

### 3-2. 職種（6つ）

**`hint` は画面に出します。**「作業の名前」ではなく「触っている対象」で選ばせるためです。

| `key` | `label` | `hint` |
| --- | --- | --- |
| `infraOnPrem` | インフラ（オンプレ・サーバ） | 物理サーバ・OS・仮想化基盤を触っている |
| `infraCloud` | インフラ（クラウド） | AWS / Azure / GCP のコンソールや IaC を触っている |
| `network` | ネットワーク | ルータ・スイッチ・ファイアウォールの設定を触っている |
| `internalIT` | 社内IT・ヘルプデスク | 利用者のPC・アカウント・問い合わせを扱っている |
| `devFront` | 開発（フロントエンド） | 画面・UI のコードを書いている |
| `devBack` | 開発（バックエンド） | サーバサイドのコードを書いている |

### 3-3. 単価

```
RATE_OPTIONS         = [40, 45, 50, ... , 115, 120]   （5万円刻み・17個）
RATE_STEP            = 5
CURRENT_RATE_MAX     = 100
CURRENT_RATE_OPTIONS = RATE_OPTIONS のうち 100 以下   （13個）
```

**現在の単価は100万まで、目標の単価は120万まで**です。
現在100万の人が、その上を目標に選べるようにするためです。

### 3-4. レイヤー

`LAYERS` は 2-1 の表のとおり。`maxRate` はその帯の上限で、
`routine: 45` / `ops: 55` / `build: 70` / `design: 90` / `arch: Number.POSITIVE_INFINITY`。

`LAYER_ORDER` は `routine: 0, ops: 1, build: 2, design: 3, arch: 4`。

### 3-5. 理解度

| `value` | `label` | `stockLabel` |
| --- | --- | --- |
| `teach` | 教えられる | 人に教えられる |
| `use` | 扱える | 扱える |
| `tried` | かじった | かじった程度 |

```
TRIED_PROGRESS             = 0.5    「かじった」＝扱えるまでの時間の50%まで到達しているとみなす
REQUIRE_TEACH_BELOW_TARGET = true   目標より下のレイヤーは「教えられる」まで求める
```

**この2つは調査データではなく、試算のために置いた前提です。画面に必ず明示します。**

### 3-6. 選択肢

```
HOLIDAY_OPTIONS   週1日 / 週1.5日 / 週2日 / 週2.5日 / 週3日以上   （値は 1 / 1.5 / 2 / 2.5 / 3）
DEADLINE_OPTIONS  半年後 6 / 1年後 12 / 1年半後 18 / 2年後 24 / 3年後 36  （単位：ヶ月）
DEADLINE_PATTERNS [6, 12, 18, 24, 36]                         結果タブ 04 の比較に使う
```

「週3日以上」の内部値は **3** です。4や5に読み替えないこと。

### 3-7. 技術項目

[`データ定義.md`](データ定義.md) を参照。**全129項目**（職種別 116 ＋ 技術以外 13）。
**値をそのまま写してください。自分で計算し直さないこと。**

## 4. ヒアリングタブ

6つのカードを縦に並べます。各カードは左上に**番号バッジ（01〜06）**と**見出し**を持ちます。
一番下に「**結果を見る**」ボタンを置き、押すと結果タブに切り替わります。

### 4-1. 01「現在の職種」

**問い：「いま、あなたが主に触っているものはどれですか」**

3-2 の6職種をボタンで選ばせます。**各ボタンに `label` と `hint` の2行**を出してください。
`hint` を出さないと、参加者が「キッティングは運用かヘルプデスクか」で迷って選べません。

初期値は **`infraCloud`**。

カードの下に、次の注記をそのまま出します。

> 「作業の名前」ではなく「触っている対象」で選んでください。
> たとえばキッティングでも、サーバのラッキングや初期構築ならインフラ（オンプレ・サーバ）、
> 利用者のPCのセットアップなら社内IT・ヘルプデスクです。
> キッティング・ヘルプデスク・監視といった仕事の“深さ”は、職種ではなく単価のレイヤーで表します。

### 4-2. 02「現在の単価」

**問い：「いまの月額単価（5万円刻み）」**

`CURRENT_RATE_OPTIONS`（40〜100万・13個）をボタンで選ばせます。初期値 **60**。

下に、選んだ単価のレイヤーを出します（`RateNote` コンポーネント）。

> この単価帯は **構築**　決まった設計を、自分の手で組み上げる

注記：「分からない場合は、だいたいの金額で構いません。結果は目標との差だけを使います。」

### 4-3. 03「現在の保有技術」

**選んだ職種の技術項目**を、**レイヤーごとに見出しを付けて**並べます。

- チェックボックス ＋ チェックした項目だけ右に理解度プルダウン（3択）
- 項目名の横に **`{useHours}／{teachHours}h`** を小さく出す
- レイヤーの見出しには、レイヤー名と `summary` を添える
- カード右上に `チェック ◯ / ◯`
- **初期状態は全部未チェック**
- チェックを入れた瞬間の理解度は **`use`（扱える）**
- チェックを外したら、その項目の理解度は保持しない（消す）

リード文：

> できるものにチェックを入れ、理解度を選んでください。項目の横の数字は
> 「扱えるまで／教えられるまで」の標準学習時間です。

> **職種を切り替えたとき**、前の職種でチェックした項目が状態に残ります。
> 計算には入らないので、**結果タブ 05 の表示でも現在の職種の項目だけに絞ってください。**
> ここを忘れると、別職種の技術が在庫に残って見えます。

### 4-4. 04「技術以外の能力」

`SOFT_SKILLS`（13項目）を、03 と同じ形式で出します。

リード文：

> 単価は技術だけで決まりません。設計より上のレイヤーでは、
> こちらが揃っているかどうかで差がつきます。数字は「扱えるまで／教えられるまで」の時間です。

### 4-5. 05「現在の空き時間」

| 入力 | 形式 | 初期値 |
| --- | --- | --- |
| 週に何日休みですか | `HOLIDAY_OPTIONS` をボタンで択一 | **2** |
| 平日1日の空き時間 | 数値入力（step 0.5 / min 0 / max 24）、単位「時間」 | **3** |
| 休日1日の空き時間 | 同上 | **6** |

自動計算して出すもの：

| 表示 | 計算 | 初期値での結果 |
| --- | --- | --- |
| 月の平日日数 | (7 − 週休日数) × 4.35 | **21.7** 日 |
| 月の休日日数 | 週休日数 × 4.35 | **8.7** 日 |
| **月の空き時間** | 平日空き × 平日日数 ＋ 休日空き × 休日日数 | **117.4** 時間 |

`4.35 × 5 = 21.75` ですが、**日数の表示だけ小数第1位で切り捨て**て `21.7` とします（四捨五入しない）。
**内部の計算には切り捨てない値（21.75）を使い続けます。**

注記：「1ヶ月＝4.35週として計算しています。」

### 4-6. 06「目標」

| 入力 | 形式 | 初期値 |
| --- | --- | --- |
| 単価を幾らまで上げたいですか（5万円刻み） | `RATE_OPTIONS`（40〜120万・17個） | **80** |
| いつまでに達成したいですか | `DEADLINE_OPTIONS` をボタンで択一 | **24**（2年後） |
| 名前 | 自由入力・**任意** | 空 |

- 目標単価の下に、そのレイヤーを出す（02 と同じ `RateNote`）
- 期限の下に、実際の年月を出す。「期限 **2028年9月**　この期限から、1日あたり何時間必要かを逆算します」
- **目標 ≦ 現在** のときは注記を出す：「目標が現在の単価と同じか、それより低くなっています。上の単価を選んでください。」
- 名前は空でも全機能が動くこと。入力されたときだけページ上部に「◯◯ さんの棚卸し」

## 5. 結果タブ

上から **判定 → 01〜07 → 出典** の順です。

### 5-0. 判定（一番上・枠を強調）

**このアプリの成果物です。** 他のカードより目立たせてください（枠を太く／アクセント色）。

**見出し（逐語）**

> **{到達年月}** までに **月{目標単価}万円** へ。毎日これをやりましょう。

**処方**

> **毎日 {1日あたりの学習時間}**　技術と、技術以外の学習
> 　　　　　　　　　　　　　　　*残り {合計}h ÷ {期限}*
> 　　　　　　　　　　　　　　　1日の空き時間 {◯} 時間 の {◯}％

時間は「**2時間11分**」「**30分**」の形にします（`hm`）。

**間に合わないとき**（1日あたりが空き時間を超える）

> このペースは、いまの空き時間より1日 {超過分} 多くなります。
> 空き時間のなかでやりきるなら、期限は {最短}後（{年月}）が最短です。

空き時間が 0 のときは：「空き時間がAIのキャッチアップだけで埋まってしまいます」ではなく、
**「まず空き時間を増やすところからです。」**

**まず、この順で手をつけます**

不足項目の**先頭3つ**を出します。各行に、項目名／到達点（扱えるまで・教えられるまで）／
`残り {◯}h ／ 約{◯}日` を出します。日数は `残り ÷ 1日あたりの学習時間` の切り上げ。

**判定文は事実だけ。** 「頑張りましょう」「厳しいですね」のような評価・励まし・否定を足さないこと。

### 5-1. 01「単価は、どのレイヤーを持てるかで決まる」

5つのレイヤーを**横に並べたカード**で出します（狭いときは折り返す）。

各カードの中身：単価帯（`40〜45万`）／レイヤー名／`summary`。

| 状態 | 見せ方 |
| --- | --- |
| 現在のレイヤー | タグ「**いまここ**」 |
| 目標のレイヤー | タグ「**目標**」＋枠をアクセント色で強調 |
| 現在より下 | 背景を薄く |
| 目標より上 | 減光する |

リード文：「単価の差は、経験年数よりも「担当できるレイヤー」で開きます。いまの位置と、目標の位置を並べています。」

注記：「レイヤーの区切りと単価帯は、公開されている単価相場の記事をもとに置いた目安です。社内の実単価に合わせて調整してください。」

### 5-2. 02「1日あたりの逆算」

**左：内訳の表**

| 期限までにやりきる学習 | 時間 |
| --- | ---: |
| 技術　*不足 ◯ 項目* | ◯ |
| 技術以外の能力　*不足 ◯ 項目* | ◯ |
| **合計** | **◯** |

**右：結果と計算式**

> **1日あたり必要な学習時間**
> **2時間11分**
> 期限 2028年9月

計算式をそのまま見せます（改行を保つこと）。

```
1595 h ÷ ( 24 ヶ月 × 30.45 日 )
＝ 1日 2.2 h
```

**下：この試算の前提**（箇条書き・逐語に近い形で必ず出す）

- 各項目には「**扱えるまで**（手を動かして成果物を出せる）」と「**教えられるまで**（なぜそれを選んだかを説明でき、人に教えられる）」の2つの標準学習時間を持たせています。資格試験の学習時間の目安をもとに置いた値で、実測値ではありません。
- **目標レイヤーの技術は「扱える」まで、それより下のレイヤーの技術は「教えられる」まで**を到達点にしています。AI が出した答えを後から説明し、技術選定の根拠を持つには、土台になっている層を「なぜそれを選んだのか」まで言える必要があるためです。
- すでに投じ終えた時間の数え方：教えられる＝教えられるまでの時間 ／ 扱える＝扱えるまでの時間 ／ かじった＝扱えるまでの時間の 50％ ／ 未チェック＝0。
- 1ヶ月＝30.45日（4.35週×7日）。1日あたりの空き時間は、月の空き時間をこの日数でならしたものです。
- **学習すれば単価が上がることを保証する計算ではありません。** 「その水準で求められる項目を、期限までに学び終えるには1日どれだけ要るか」を出しているだけです。

### 5-3. 03「何を、どの順で学ぶか」

不足している**技術**項目の表。**浅いレイヤーから、残り時間の短いものから**並べます。

| 列 | 内容 |
| --- | --- |
| # | 連番 |
| 学ぶこと | 項目名。チェック済みなら「いま：扱える」「いま：かじった」を添える |
| レイヤー | レイヤー名（タグ） |
| **到達点** | **扱える** / **教えられる**（教えられるはアクセント色のタグ） |
| 必要 | その到達点に必要な時間 |
| 残り | 必要 − すでに投じ終えた時間 |
| 累積 | ここまでの残りの合計 |
| 完了 | 上から順に学んだとき、その項目を学び終える日 |

「完了」は `累積 ÷ 1日あたりの学習時間` を切り上げた日数。**60日を超えたら「約◯ヶ月目」**に切り替えます。

全部チェック済みのときは「目標のレイヤーで求められる技術は、すべてチェック済みです。」

### 5-4. 04「期限を変えると、1日あたりがどう変わるか」

`DEADLINE_PATTERNS`（6/12/18/24/36ヶ月）で割った表。

| 期限 | いつ | 1日あたり | 空き時間の |
| --- | --- | ---: | ---: |
| 6ヶ月後 | 2027年3月 | 8時間44分 | 超える |
| … | | | |

空き時間を超える行は、割合の代わりに「**超える**」と出し、薄い色にします。
いま選んでいる期限の行を**アクセント色**にします。

注記：「「超える」の行は、いまの空き時間（1日 ◯ 時間）では足りない期限です。」

### 5-5. 05「いまの技術在庫」

チェック済みの**技術**項目を、理解度の3階層に分けてタグで並べます。

| 階層 | 見出し | タグの見た目 |
| --- | --- | --- |
| `teach` | 人に教えられる | 朱色で塗りつぶし |
| `use` | 扱える | 薄い朱色 |
| `tried` | かじった程度 | 枠線のみ |

- カード右上に総数。各階層の見出しにも件数
- **現在の職種の項目だけを出す**（4-3 の注意）
- 1件もないとき：「ヒアリングのタブでチェックしてみてください」
- ある階層だけ0件のとき：`—` を出す。階層自体は消さない

### 5-6. 06「技術以外で、足りていないもの」

不足している `SOFT_SKILLS` を、項目名／レイヤー／残り時間 で並べ、最後に合計を出します。

リード文：「設計より上のレイヤーは、技術だけでは届きません。ここが空いていると、技術が揃っても単価が上がりにくくなります。」

### 5-7. 07「今日、最初に手をつけること」

> **中身は必ず空欄です。**

## 6. 計算

**計算は `lib/calc.ts` の純関数にまとめます。** 入力を受け取り値を返すだけ。JSX を書かない。

### 6-1. 入力状態（`FormState`）

| フィールド | 型 | 初期値 |
| --- | --- | --- |
| `role` | `RoleKey` | `'infraCloud'` |
| `currentRate` | number | 60 |
| `goalRate` | number | 80 |
| `skills` | `Record<string, SkillLevel>` | `{}` |
| `softSkills` | `Record<string, SkillLevel>` | `{}` |
| `weekdayFree` | number | 3 |
| `holidayFree` | number | 6 |
| `holidayPerWeek` | number | 2 |
| `deadlineMonths` | number | 24 |
| `name` | string | `''` |

### 6-2. 小さい関数

```
clampHours(x)        有限でなければ 0、そうでなければ 0〜24 に収める
layerOfRate(rate)    LAYERS を先頭から見て、rate <= maxRate の最初のレイヤーを返す
layerByKey(key)      LAYERS から引く
```

### 6-3. 到達点と残り時間（ここが中核）

```
progressHours(item, level)          … すでに投じ終えた時間
  teach     → item.teachHours
  use       → item.useHours
  tried     → item.useHours × TRIED_PROGRESS   （＝ × 0.5）
  未チェック → 0

requiredLevelOf(item, targetLayer)  … 求められる到達レベル
  REQUIRE_TEACH_BELOW_TARGET が false なら常に 'use'
  LAYER_ORDER[item.layer] < LAYER_ORDER[targetLayer] なら 'teach'、そうでなければ 'use'

requiredHours(item, targetLayer)
  requiredLevelOf が 'teach' なら item.teachHours、そうでなければ item.useHours

remainingHours(item, level, targetLayer)
  max(0, requiredHours(...) − progressHours(...))
```

### 6-4. 集計

```
targetLayer = layerOfRate(goalRate)

対象の項目 = その職種の技術項目のうち LAYER_ORDER[layer] <= LAYER_ORDER[targetLayer]
             （技術以外も同じ条件で絞る）

不足リスト = 対象の項目のうち remainingHours > 0 のもの
             並び順：レイヤーの浅い順 → 残り時間の短い順
             累積（cumulative）を先頭から足していく

techHours  = 技術の残りの合計
softHours  = 技術以外の残りの合計
totalHours = techHours + softHours
```

### 6-5. 空き時間と1日あたり

```
月の休日日数 = holidayPerWeek × 4.35
月の平日日数 = (7 − holidayPerWeek) × 4.35
月の空き時間 = clampHours(weekdayFree) × 月の平日日数
             + clampHours(holidayFree) × 月の休日日数
1日の空き時間 = 月の空き時間 ÷ 30.45

1日あたり必要な学習時間 = totalHours ÷ ( max(1, deadlineMonths) × 30.45 )

空き時間に占める割合 = 月の空き時間 > 0 ? 1日あたり ÷ 1日の空き時間 × 100 : null
間に合うか          = 1日あたり <= 1日の空き時間
超過分              = max(0, 1日あたり − 1日の空き時間)
空き時間で収まる最短 = totalHours == 0 ? 0
                     : 1日の空き時間 > 0 ? totalHours ÷ (1日の空き時間 × 30.45)
                     : null
```

### 6-6. 期限

```
targetDate(base, months)        base の月初に months（切り上げ）を足した Date
dailyStudyForMonths(total, m)   m > 0 ? total ÷ (m × 30.45) : Infinity
```

**`null` を返したときは、画面に `—` と出します。** `0` や `NaN` や `Infinity` を出さないこと。

## 7. 表示の整形

| ルール | 対象 | 例 |
| --- | --- | --- |
| 小数第1位まで必ず出す（`n1`） | 時間 | `3.0` `117.4` |
| 整数に四捨五入（`n0`） | ％ | `57` |
| **小数第1位で切り捨て**（`trunc1`） | **月の日数だけ** | 21.75 → `21.7` |
| 整数（`hours`） | 学習時間の合計 | `1595` |
| 「2時間11分」「30分」（`hm`） | 1日あたりの時間 | `2時間11分` |

| 「2年2ヶ月」「9ヶ月」（`span`） | 期間 | |

- **数字は等幅フォントで桁を揃える。** 小数点の位置が縦に揃うこと
